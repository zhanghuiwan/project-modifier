# CHANGELOG 与规划文档模板

本文档提供 CHANGELOG 记录模板和修改规划文档模板。

---

## 一、CHANGELOG 模板

### 1.1 文件格式

CHANGELOG.md 按时间倒序排列，最新修改在最上面：

```markdown
# Changelog

## [YYYY-MM-DD] 修改类型：简要描述

### 变更内容
- 修改了 XXX（原因：...）
- 新增了 YYY（原因：...）
- 删除了 ZZZ（原因：...）

### 影响范围
- 涉及模块：...
- 涉及文件：...
- 接口变更：有/无（如有，列出变更的接口）

### 测试结果
- 已有测试：全部通过 / N 个失败
- 新增测试：N 个 / 无

### 回退方案
- 回退方式：`git revert <commit-hash>`
- 回退影响：...

---

## [YYYY-MM-DD] 修改类型：简要描述

### 变更内容
...
```

### 1.2 修改类型

| 类型 | 说明 | 示例 |
|------|------|------|
| Bug修复 | 修复代码缺陷 | `Bug修复：修复用户登录后重定向错误` |
| 新增功能 | 添加新功能 | `新增功能：添加用户头像上传` |
| 删除功能 | 移除已有功能 | `删除功能：移除旧版消息通知` |
| 接口调整 | 修改API接口 | `接口调整：用户列表接口增加分页参数` |
| 重构 | 代码重构不改变功能 | `重构：提取认证中间件` |
| 配置变更 | 修改配置 | `配置变更：更新数据库连接池大小` |

---

## 二、修改规划文档模板（中型/大型修改）

### 2.1 文件位置

修改规划文档存放在项目 `docs/` 目录下，命名格式：`modification-plan-<简要描述>.md`

### 2.2 模板

```markdown
# 修改规划文档

## 1. 修改概述

### 1.1 修改目标
[要达成什么效果，解决什么问题]

### 1.2 修改类型
[新增功能 / Bug修复 / 删除功能 / 接口调整 / 重构 / 混合]

### 1.3 修改规模
[中型 / 大型]

## 2. 当前状态

### 2.1 相关代码现状
[描述与修改相关的代码当前是什么状态]

### 2.2 已知问题
[当前代码中与本次修改相关的问题]

## 3. 修改方案

### 3.1 方案概述
[整体方案的简要描述]

### 3.2 修改步骤

#### 步骤 1：[步骤名称]

**目标**：[本步骤要达成什么]

**操作**：
- [具体操作 1]
- [具体操作 2]

**涉及文件**：
- `path/to/file1` — [修改内容]
- `path/to/file2` — [修改内容]

**验证方式**：
- [如何验证本步骤完成且正确]

---

#### 步骤 2：[步骤名称]
[同上格式]

---

#### 步骤 N：[步骤名称]
[同上格式]

### 3.3 步骤依赖关系

```
步骤 1 → 步骤 2 → 步骤 3
                 ↘ 步骤 4
```

## 4. 影响范围

### 4.1 直接受影响的模块/文件
| 模块/文件 | 变更类型 | 说明 |
|----------|---------|------|
|          | 修改/新增/删除 | |

### 4.2 间接受影响的模块/文件
| 模块/文件 | 影响方式 | 是否需要调整 |
|----------|---------|------------|
|          | 调用链影响 | 是/否 |

### 4.3 接口变更
| 接口 | 变更类型 | 变更内容 |
|------|---------|---------|
|      | 新增/修改/删除 | |

### 4.4 数据结构变更
| 数据结构 | 变更类型 | 变更内容 |
|---------|---------|---------|
|         | 新增字段/修改字段/删除字段 | |

## 5. 风险评估

| 风险 | 可能性 | 影响 | 应对措施 |
|------|--------|------|---------|
|      | 高/中/低 | 高/中/低 | |

## 6. 回退方案

### 6.1 回退方式
- 回退到 commit: <修改前的 commit hash>
- 回退命令: `git revert <range>` 或 `git reset --hard <commit>`

### 6.2 回退影响
[回退后会失去什么]

### 6.3 数据回滚（如涉及数据库变更）
[如何回滚数据库变更]

## 7. 测试计划

### 7.1 已有测试
[哪些已有测试与本次修改相关，修改后需要运行]

### 7.2 新增测试
| 测试用例 | 覆盖场景 | 优先级 |
|---------|---------|--------|
|         | 正常/异常/边界 | |

### 7.3 手动验证项
[需要手动验证的场景]

## 8. 文档更新计划

| 文档 | 更新内容 | 是否必须 |
|------|---------|---------|
|      |         | 是/否 |

## 9. 用户确认

- [ ] 修改方案已确认
- [ ] 影响范围已确认
- [ ] 风险已确认
- [ ] 回退方案已确认

确认人：________  日期：________
```

```markdown

**描述**：[接口功能]

**请求参数**：
| 字段 | 类型 | 必填 | 描述 |
|------|------|------|------|
|      |      |      |      |

**响应参数**：
| 字段 | 类型 | 描述 |
|------|------|------|
|      |      |      |

**请求示例**：
```json
{}
```

**响应示例**：
```json
{}
```
```

### 变更详情

#### 表：[表名]

**变更类型**：[新增字段 / 修改字段 / 删除字段]

| 字段名 | 变更类型 | 原类型 | 新类型 | 说明 |
|--------|---------|--------|--------|------|
|        |         |        |        |      |

### 迁移方案
[如何从旧结构迁移到新结构]

### 回滚方案
[如何从新结构回退到旧结构]
```

## 五、项目概览文档模板

```markdown

## 基本信息
- 项目名称：
- 技术栈：
- 项目类型：[前端/后端/全栈]

├── src/          — [说明]
├── tests/        — [说明]
├── docs/         — [说明]
├── config/       — [说明]
└── ...
```

|        |         |      |

| 问题 | 位置 | 说明 |
|------|------|------|
|      |      |      |
```
