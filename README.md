# Project Modifier

修改已有项目的全流程管理 Skill，为 AI Agent 提供安全、可控的项目修改能力。

## 概述

当你需要修改一个已有项目（修 bug、加功能、删功能、重构等）时，这个 Skill 提供**代码为主、渐进理解、规划先行、安全修改**的完整流程，确保修改可回退、可验证、可追溯。

**本 Skill 完全独立运行，不依赖任何其他 Skill。**

### 核心机制

| 机制 | 说明 |
|------|------|
| 💻 代码为主 | 以实际代码为真相源，文档仅做参考 |
| 🔍 渐进理解 | 分3层理解项目，只聚焦修改相关区域 |
| 📏 规模分级 | 小/中/大三种规模对应不同重量的流程 |
| 📋 规划文档驱动 | 中大型修改必须先形成规划文档再执行 |
| 🛡️ 三级回退 | 修代码 → 回退本次修改 → 回退接手前(需用户确认) |

### 修改流程

```
M0 项目评估 → M1 代码理解 → M2 修改点分析+规模判断
                                    │
                                    ├── 小型 → 直接修改 → 测试 → 提交
                                    │
                                    └── 中型/大型 → M3 规划文档 → M4 执行修改 → M5 验证收尾
```

```bash

npx skills add zhanghuiwan/project-modifier

```

## 触发方式

当用户使用以下任何表述时，Skill 会自动触发：

**中文**：帮我修个bug、给项目加个功能、删除这个模块、重构一下、改一下接口、调试、补丁、更新、升级、迁移……

**English**：fix a bug、add a feature、refactor this、modify the project、debug、patch、hotfix、tweak、adjust、update、upgrade、remove、delete、migrate……

> **优先级**：当目标为已有项目时，此 Skill 优先于项目构建类 Skill。

## 使用示例

```
用户：帮我修一下登录页面的跳转问题
→ Skill 触发 → M0评估 → M1理解 → M2判定小型 → 直接修复 → 测试 → 提交

用户：给项目加一个用户头像上传功能
→ Skill 触发 → M0评估 → M1理解 → M2判定中型 → M3规划文档 → 用户确认 → M4执行 → M5验证

用户：Refactor the authentication module
→ Skill 触发 → M0评估 → M1理解 → M2判定大型 → M3规划文档(含接口文档+测试用例) → 用户确认 → M4执行 → M5验证
```

## 规模判断

| 规模 | 判断依据 | 流程 |
|------|---------|------|
| 小型 | ≤3 个文件，不影响接口和数据结构 | 直接修改 → 测试 → 提交 |
| 中型 | 3-10 个文件，涉及接口或数据结构变更 | 规划文档 → 执行 → 验证 |
| 大型 | >10 个文件，或涉及架构层面变更 | 规划文档(含接口/测试文档) → 执行 → 验证 |

## 回退策略

```
Level 1 — 修复代码：代码 bug，方案没问题 → 修代码 → 重测
Level 2 — 回退本次修改：方向偏差 → git revert → 重新执行
Level 3 — 回退到接手前：需要回退到修改开始之前 → ⚠️ 必须用户确认 → 回退 → 从M1重新开始
```

> **Level 3 特别说明**：回退到接手前可能丢失非本次修改的已有功能，必须与用户确认。

## 代码理解策略

分3层渐进理解，不试图一次性理解整个项目：

```
第一层：宏观结构 → 目录、入口文件、配置、依赖清单
第二层：数据流   → 数据入口、数据出口、流转路径
第三层：目标区域 → 只深入理解与本次修改相关的代码
```


## 设计理念

1. **代码为主** — 已有项目中，代码是唯一确定的真实。文档可能过时，但代码是实际运行的。所有理解和决策都基于代码。

2. **渐进理解** — 不要试图理解整个项目。先宏观把握，再理解数据流，最后聚焦修改区域。理解深度随修改规模而定。

3. **规划先行** — 中大型修改必须先形成规划文档。规划文档是修改全程的指引，不允许偏离文档实现。

4. **安全修改** — 每一次修改都要确保可回退（Git 保护）、可验证（测试）、可追溯（CHANGELOG）。

## 与 Project Builder 的区别

| 维度 | Project Builder | Project Modifier |
|------|----------------|-----------------|
| 场景 | 从零搭建新项目 | 修改已有项目 |
| 真相源 | 文档 | 代码 |
| 起点状态 | 空白 | 已有代码（可能混乱） |
| 核心流程 | P0-P7 八个阶段 | M0-M5 按规模分级 |
| 回退级别 | 四级 | 三级 |

两者完全独立，互不依赖。
